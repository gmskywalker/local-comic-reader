# 📚 本地漫画阅读器

**把散落在文件夹里的漫画，整理成可离线使用的下拉式网页书架。**

Windows · 无需安装服务器 · 不上传漫画 · 支持任意章节名与自定义顺序

</div>

---

## 这是什么？

这是一套面向 Windows 的本地漫画工具，由三个可直接双击的运行文件组成：

| 文件 | 用途 |
| --- | --- |
| `漫画阅读器.html` | 选书、章节目录与连续下拉阅读；阅读进度保存在浏览器本机 |
| `漫画更新器.vbs` | 扫描当前目录的漫画，核验图片并重新生成阅读网页 |
| `new/漫画整理器.vbs` | 合并分散章节、拆分总集、调整顺序、设置封面与章节标题 |

脚本不联网、不上传图片，也不会修改原漫画。整理器始终复制到新的输出文件夹，并把输出图片统一命名为 `0001`、`0002`……

> [!IMPORTANT]
> 仓库和压缩包不包含任何漫画、封面、阅读记录或作者作品。请只处理你有权保存和阅读的内容。

## 下载

直接下载仓库中的 [`local-comic-reader-windows.zip`](./release/local-comic-reader-windows.zip)，解压到任意本地文件夹即可。

也可以克隆仓库；真正运行时只需要上表中的三个文件。

## 30 秒开始使用

解压后的建议布局：

```text
我的漫画/                         ← 文件夹名称和盘符可以随时更改
├─ 漫画阅读器.html
├─ 漫画更新器.vbs
├─ 漫画 A/
│  ├─ cover.jpg                   ← 可选封面
│  ├─ 第1话/
│  │  ├─ 0001.jpg
│  │  └─ 0002.jpg
│  └─ 第2话/
│     ├─ 0001.jpg
│     └─ 0002.jpg
└─ new/
   ├─ 漫画整理器.vbs
   └─ 刚下载、尚未整理的漫画文件夹/
```

1. 把漫画文件夹放到 `漫画更新器.vbs` 所在的漫画根目录。
2. 双击 `漫画更新器.vbs`，勾选需要出现在书架里的漫画。
3. 选择更新完成后是否自动打开阅读器，然后点击更新。
4. 以后直接打开 `漫画阅读器.html` 阅读；新增漫画后再运行一次更新器。

所有网页和图片都使用相对路径。漫画根目录改名、移动到其他盘，或者复制到另一台电脑后，内部链接仍然有效。

## 阅读体验

- 网站式纵向下拉阅读，图片自动等宽且无缝衔接。
- 阅读页工具栏保持置顶，只显示“当前话 / 总话数”和必要按钮。
- 多档缩放，行为接近浏览器的 `Ctrl +` / `Ctrl -`，只影响阅读页。
- 背景颜色和文字颜色使用两个独立按钮。
- 背景、文字均有常用预设、颜色选择器和四个自定义收藏槽。
- 自动保存漫画、章节、图片位置；可继续上次阅读或清除进度。
- 选书页、漫画目录页和阅读页均适配常见手机浏览器宽度。

> 手机可以打开这些网页，但手机浏览器通常不能直接访问电脑磁盘。可把整个漫画文件夹复制到手机，或把整理后的章节转换为 CBZ 后使用专业漫画 App。

## 更新器支持哪些目录？

### 1. 一般多话漫画

```text
漫画名/
├─ cover.jpg
├─ 第1话/
├─ 4.5话/
├─ 特典/
└─ 任意其他章节名/
```

章节文件夹不再强制要求“第 X 话”。`特典`、`番外篇`、`after` 或任何其他名称都能作为章节：

- 有整理器元数据时，严格按你在整理器中确定的顺序。
- 没有元数据时，按章节文件夹名称进行自然排序。
- `4.5`、`8.5` 等小数章节可正常显示。
- `1.01话` 或纯文字 `特典` 若应放到最后，请在整理器里直接上移、下移；显示标题与排序位置彼此独立。

### 2. 单文件夹单行本

```text
漫画名/
├─ 0001.jpg
├─ 0002.jpg
└─ 0003.jpg
```

根目录直接放正文图片时，会自动作为一话漫画处理，不必为了阅读额外建立“第1话”文件夹。

### 3. 复合文件名或整本总集

例如：

```text
P01_001.jpg
P01_002.jpg
P02_001.jpg
P02_002.jpg
```

整理器能识别“章节组 + 页码”模式，并自动生成章节行。识别不到固定模式时，则按完整文件名自然排序，之后复制并标准化为纯数字文件名。

### 图片格式

支持：`.jpg`、`.jpeg`、`.png`、`.webp`、`.gif`、`.bmp`、`.avif`。

`cover.jpg`、`cover.png` 等会优先作为漫画封面；没有封面文件时使用第一张正文图。整理器也允许在来源表格中单独勾选封面来源。

## 漫画整理器

把 `漫画整理器.vbs` 放在下载区（通常是 `new`）并双击运行。它适合两类常见工作：

### 合并多个文件夹为一部漫画

1. 勾选多个来源文件夹并载入。
2. 每个来源会先生成一行章节。
3. 可编辑显示标题、章节名和排序位置。
4. 多个来源也可以合并到同一话：复制行或调整每行图片范围即可。
5. 在最后一列勾选封面来源。

### 把总集拆成多话

1. 载入包含全部图片的文件夹。
2. 选择该行，按图片范围拆分。
3. 为每一行设置起始页、结束页、章节编号和章节标题。
4. 用“上移 / 下移”确定真实阅读顺序。

章节编号只是显示内容，不负责最终排序。因此 `第1.01话 特典`、`特典话`、`番外` 等标题都可以放在任意位置。

“按当前顺序编号”支持从选中行的下一行继续：

- 当前行为 `第3话`，后面自动编号为 `4、5、6……`。
- 当前行为 `4.5话`，后面自动编号为 `5、6、7……`。
- 没有数字的特殊章节不会阻止你手动命名和排序。

## 图片顺序与缺页核验

工具会尽量在“容易判断缺页”与“兼容各种下载命名”之间取得平衡：

| 文件名情况 | 排序和核验方式 |
| --- | --- |
| `0001.jpg`、`0002.jpg`…… | 按数字排序，并检查起始编号、断号和重复号 |
| `P01_001.jpg`、`P01_002.jpg`…… | 识别章节组和页码；在组内检查重复与明显断号 |
| 无法识别的名称 | 按名称自然排序；因没有可靠页码，只提示无法严格判断缺页 |

自然排序会把 `2.jpg` 放在 `10.jpg` 前，而不是简单按字符排序。若同一文件夹混用了多套命名规则，建议先在整理器中预览并手动确认。

## 元数据是做什么的？

整理器会在输出漫画中写入 JSON 元数据，用于记录：

- 章节的严格阅读顺序；
- 每话显示名称和独立章节标题；
- 封面来源；
- 整理器版本及必要的结构信息。

JSON 不是图片，也不会影响原文件。没有 JSON 时更新器仍可工作，只是改用文件夹名称自然排序；有 JSON 时则严格服从你保存的顺序。

## 常见问题

<details>
<summary><strong>双击 VBS 后为什么没有黑色命令行窗口？</strong></summary>

这是正常设计。两个 VBS 文件会隐藏 PowerShell 控制台，只显示图形界面；关闭图形界面后后台进程也会退出。

</details>

<details>
<summary><strong>Windows 提示脚本来自未知发布者怎么办？</strong></summary>

这些脚本没有商业代码签名。可先在 `source/` 阅读完整 PowerShell 源码；VBS 只是把相应源码压缩封装后隐藏运行。请只从本仓库下载，不要运行来源不明的同名文件。

</details>

<details>
<summary><strong>为什么某部漫画没有出现在更新器候选列表？</strong></summary>

确认漫画目录至少包含一个有支持格式图片的章节文件夹，或在漫画根目录直接包含正文图片。空文件夹、只有 JSON 而没有图片的目录不会成为候选漫画。

</details>

<details>
<summary><strong>只想整理总集中的一部分，未选图片为什么会警告？</strong></summary>

整理器会列出未使用的图片并要求二次确认，这是为了防止误漏。确认本来就不需要这些图片后可以继续，不会再把它当成致命错误。

</details>

<details>
<summary><strong>可以把 index.html 改名吗？</strong></summary>

总书架固定为 `漫画阅读器.html`；每部漫画目录中的 `index.html` 是更新器生成的章节入口，不建议手动改名，否则下次更新会重新生成且链接可能失效。

</details>

## 从源码重新打包

仓库的三个运行文件是发布产物，完整源码位于 `source/`：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\source\build-single-file-tools.ps1 `
  -OutputDirectory .\.tmp
```

生成后：

- 把 `.tmp/漫画更新器.vbs` 放到漫画根目录；
- 把 `.tmp/漫画整理器.vbs` 放到漫画根目录下任意下载区，例如 `new/`。

VBS 启动器使用相对位置确定工作区，不绑定盘符或绝对路径。

## 已知边界与建议

- 如果同一漫画目录同时在根目录放正文图片、又放多个章节子文件夹，结构含义不明确；建议先用整理器统一结构。
- 对完全无数字规律的文件名，只能自然排序，无法可靠证明是否缺页。
- 超长路径可能受到 Windows 或解压软件限制；建议漫画根目录不要嵌套过深。
- 两个文件同名但扩展名不同会造成页码重复歧义，整理前应检查。
- HTML 阅读器适合本地离线阅读；跨设备同步进度、网络书库和多人共享不在本工具范围内。
