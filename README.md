# 本地漫画阅读器

把本地图片漫画变成离线网页书架，也可以整理章节并导出为 CBZ、EPUB 或无缝长页 PDF。

**Windows · 单文件工具 · 相对路径 · 不上传漫画 · 任意章节名 · 自定义阅读顺序**

</div>

---

## 项目简介

这是一套完全在本机工作的 Windows 漫画管理工具。它不提供漫画内容，也不连接漫画网站；扫描、核验、整理、网页生成和格式导出都在本地完成。

| 文件 | 用途 |
| --- | --- |
| `漫画阅读器.html` | 本地书架入口，由更新器生成和维护 |
| `漫画更新器.vbs` | 扫描漫画目录、核验图片并生成书架、目录页和连续阅读页 |
| `漫画整理器.vbs` | 合并或拆分章节、编辑顺序/标题/简介并标准化图片文件名 |
| `漫画导出器.vbs` | 导出分话 CBZ、整本 CBZ、EPUB 或分话长页 PDF |

三个 VBS 都是单文件工具：完整 PowerShell 程序已经压缩嵌入其中。双击后只显示图形界面，不会留下黑色命令行窗口；关闭界面后后台进程也会退出。

> [!IMPORTANT]
> 仓库与发布压缩包不包含任何漫画、封面、阅读记录或作者作品。请只处理你有权保存和阅读的内容。

## 下载与放置方式

下载 [`release/local-comic-reader-windows.zip`](./release/local-comic-reader-windows.zip)，或克隆整个仓库。

更新器、导出器和整理器都以“自己所在的文件夹”为工作区，所以漫画根目录可以改名、换盘符或整体移动。仓库与压缩包把三个 VBS 放在同一级，方便下载；实际使用时可以按需要摆放。

### 最简单的布局

```text
我的漫画/
├─ 漫画阅读器.html
├─ 漫画更新器.vbs
├─ 漫画导出器.vbs
├─ 漫画整理器.vbs
├─ 漫画 A/
│  ├─ cover.jpg
│  ├─ 第1话/
│  │  ├─ 0001.jpg
│  │  └─ 0002.jpg
│  └─ 特典/
│     └─ 0001.jpg
└─ 漫画 B/
```

整理器放在这里也能运行，它会把当前根目录中的漫画作为可选来源。

### 推荐的防混淆布局

如果不想把“已经进入书架的漫画”和“刚下载、等待整理的文件夹”混在一起，建议自己建立一个 `new`、`待整理` 或任意名称的子文件夹，并把整理器放进去：

```text
我的漫画/
├─ 漫画阅读器.html
├─ 漫画更新器.vbs
├─ 漫画导出器.vbs
├─ 已整理漫画 A/
└─ new/
   ├─ 漫画整理器.vbs
   ├─ 刚下载的来源文件夹 1/
   └─ 刚下载的来源文件夹 2/
```

整理结果会写到整理器同级的 `整理完成` 文件夹，确认无误后再手动复制到漫画根目录。子文件夹不必叫 `new`，中文名、其他盘符和任意层级都可以。

## 快速开始：生成离线网页书架

1. 把 `漫画更新器.vbs` 放在漫画根目录。
2. 双击更新器并勾选要进入书架的漫画。
3. 首次或需要重建整个书架时点击“全部更新”；后来加入新漫画时直接勾上它，更新旧漫画时将该项取消后重新勾上，再点击“加入 / 更新本次勾选”。
4. 底部会持续显示核验和生成进度。任务完成后会弹窗提示，主界面不会自动关闭。
5. 打开生成的 `漫画阅读器.html`。

更新器支持：

- “全部更新”重建所有勾选漫画，并以当前勾选决定书架内容；
- “加入 / 更新本次勾选”只处理本次新勾上的项目：新漫画会加入书架，旧漫画会重新生成，其他既有书架内容保持不动；
- 主窗口常驻，任务期间在底部显示当前核验/生成进度；
- 可选择完成后是否自动打开阅读器；
- 已有元数据时严格采用元数据顺序，没有元数据时按章节名自然排序；
- 自动核对网页引用的图片数量，防止静默漏图；
- `第3话 前编` 与 `第3话 中编` 会作为两个独立章节，不会因数字相同而冲突。

网页阅读器提供：

- 所有图片等宽、无缝、从上到下连续阅读；
- 阅读页置顶工具栏，只保留“当前话 / 总话数”和工具按钮；
- 25%～500% 多档缩放，只影响阅读页，不改变书架与目录页；
- 背景颜色和文字颜色使用两个独立按钮；
- 预设颜色、调色板和自定义收藏色；
- 漫画、章节和图片位置的本地阅读进度；
- 桌面与手机浏览器自适应布局。

每部漫画的 `index.html` 和各话阅读页都生成在漫画根目录，不会往每话图片文件夹中散落 HTML。网页使用相对路径引用图片。

## 支持的漫画结构

### 多章节漫画

```text
漫画名/
├─ cover.jpg
├─ 第1话 开始/
├─ 第3话 前编/
├─ 第3话 中编/
├─ 第4.5话/
├─ 特典/
└─ after/
```

章节文件夹不要求必须叫“第 X 话”。`特典`、`番外1`、`后记`、`插画集`、`after`、英文名或其他任意名称都能使用。

- 有有效 `元数据.json` 时，更新器、整理器和导出器严格采用其中的阅读顺序与显示标题；
- 没有元数据时，按文件夹名称自然排序；
- `1.01`、`4.5`、`8.5` 等小数话序可以保留；
- 特殊话实际放在哪里由元数据中的行顺序决定，不受显示编号限制。

工具在匹配元数据章节名时兼容 Windows 文件名规则。例如元数据里的半角 `?`、`:`、末尾空格或末尾句点，即使被 Windows 改成全角字符或自动删掉，也不会误判为另一个章节。

### 根目录单行本

```text
漫画名/
├─ 0001.jpg
├─ 0002.jpg
└─ 0003.jpg
```

正文图片直接位于漫画根目录时，会自动作为一话处理，不需要额外创建“第1话”文件夹。没有 `cover.jpg` 时可以自动采用第一张正文图作为封面。

### 复合命名或总集

```text
P01_001.jpg
P01_002.jpg
P02_001.jpg
P02_002.jpg
```

整理器会尝试识别“章节组 + 页码”并生成多行章节。无法识别固定格式时，按完整文件名自然排序。输出时只复制图片到新漫画文件夹，并统一重命名为 `0001`、`0002`……，不会改动原文件。

支持 `.jpg`、`.jpeg`、`.png`、`.webp`、`.gif`、`.bmp`、`.avif`。

## 漫画整理器

整理器适合两类常见情况：多个文件夹实际属于同一部漫画，以及一个总集图片文件夹需要拆成多话。

主要功能：

- 一个来源拆成多话，或多个来源合成一话；
- 按图片起止范围拆分总集；
- 拖动/上移/下移决定真实阅读顺序；
- 为每话单独填写话序、特殊标签和章节标题；
- 输出漫画名称既可编辑，也可从已载入来源名称中下拉选择；
- 简介默认跟随漫画名称来源，确认编辑后固定，不再随名称来源变化；
- 可从含有 `description`、`intro`、`summary`、`desc`、`简介` 或 `簡介` 的来源元数据中采用简介；
- 在表格最后一列选择封面来源；
- “重新扫描来源文件夹库”刷新工作区与已载入章节数量；
- “载入新增文件夹”追加新来源，不重置已经编辑的行；
- “重新载入所选文件夹”明确重建表格；
- 保存、加载和核验整理方案；
- 大型方案会缓存来源章节扫描结果，加载 100 话以上的方案时不再为每一行重复扫描整个漫画，并在底部显示当前载入行数；
- 只使用总集中的一部分时列出遗漏内容并二次确认，而不是直接报错。

如果来源漫画含有效 `chapterInfos.order`，载入时优先采用该顺序；配置缺失或无效时才回退到名称自然排序。

“从选中行后续编号”会从当前行的下一行继续：选中第3话后从4开始，选中第4.5话后从5开始。`特典话`、`番外1`、`后记` 等没有传统数字编号的名称可以直接保留和移动。

## 图片顺序与缺页检查

| 文件名情况 | 排序与核验 |
| --- | --- |
| `0001.jpg`、`0002.jpg`…… | 按数字排序，并检查起始编号、断号和重复号 |
| `P01_001.jpg`、`P01_002.jpg`…… | 识别章节组与页码，在组内检查重复及明显断号 |
| 无法识别的名称 | 按完整名称自然排序；提示无法严格证明是否缺页 |

自然排序会把 `2.jpg` 放在 `10.jpg` 前。遇到混合命名或不能可靠判断顺序时，工具会提示用户确认，不会静默丢弃已找到的图片。

## JSON 元数据有什么用？

整理器输出的 `元数据.json` 用来记录：

- 章节的严格阅读顺序；
- 每话的显示编号和独立标题；
- 漫画简介与简介来源；
- 封面来源；
- 整理器版本和必要结构信息。

没有 JSON 时三个工具仍能工作，只是改用名称自然排序。JSON、HTML 和整理方案不会被塞进 CBZ、EPUB 或 PDF；导出文件只包含阅读所需内容。

## 漫画导出器

把 `漫画导出器.vbs` 放在漫画根目录并双击。导出器会记住上次关闭时的导出方式、选项和输出目录。

支持四种方式：

| 方式 | 适用场景 |
| --- | --- |
| 每话一个 CBZ（推荐） | Mihon 等漫画阅读器；手机书架一部漫画，打开后列出各话 |
| 整部漫画一个 CBZ | 只要求顺序阅读，不要求可靠章节目录 |
| 整部 EPUB | ReadEra 等电子书阅读器；一本书带可点击章节目录 |
| 每话一个无缝长页 PDF（推荐） | 每话生成一个 PDF，所有图片拼成无间隙长页 |

其他选项：

- 可把总封面放在第一话或整本开头；
- 可在导出文件夹名称后标注 `CBZ`、`EPUB`、`PDF`；
- 已有同名导出时对应漫画会变灰，默认防止重复；
- 开启“同名时自动加（1）（2）继续导出”后可以保留多个版本；
- 可选择完成后打开输出目录；
- 导出大体量漫画时窗口仍可正常响应，底部会实时显示当前漫画、当前话和当前图片；
- 元数据中的章节顺序、标题、作者和简介会在格式允许时写入导出结果。

### Mihon：一部漫画、多话、无缝长条

选择“每话一个 CBZ”，把导出的整个漫画文件夹复制到手机：

```text
Mihon/local/
├─ 漫画 A/
│  ├─ 001 - 第1话.cbz
│  └─ 002 - 特典.cbz
└─ 漫画 B/
   └─ 001 - 全一话.cbz
```

在 Mihon 中进入“浏览 → 图源 → 本地来源”并刷新。打开章节后进入阅读器设置，把本系列阅读模式设为 `长条模式（Long strip）`。

- [Mihon 官方下载](https://mihon.app/download/)
- [Mihon 本地漫画说明](https://mihon.app/docs/guides/local-source/)
- [Mihon 阅读模式说明](https://mihon.app/docs/guides/reader-settings)

### ReadEra：一本 EPUB、可点击目录

选择“整部 EPUB”后，把 `.epub` 复制到手机并让 ReadEra 扫描。每部漫画在书架中显示一本，目录中的章节可以点击。水平分页、垂直翻页或连续滚动由阅读 App 决定；若必须获得网页漫画式无缝长条，优先使用 Mihon + 分话 CBZ。

## VBS 和 EXE 有什么区别？

VBS 是由 Windows Script Host 执行的脚本；EXE 是 Windows 可执行程序，可能是原生程序，也可能只是脚本与运行环境的封装。

本项目选择 VBS，是为了在不附带额外运行库的情况下实现单文件、无黑框、相对路径和可审查源码。EXE 更方便设置图标、版本信息和数字签名，但未签名 EXE 同样可能触发 SmartScreen，功能也不会天然更强。

## 从源码重新打包

完整 PowerShell 源码位于 `source/`：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\source\build-single-file-tools.ps1 `
  -OutputDirectory .\.tmp
```

生成：

- `.tmp/漫画更新器.vbs`
- `.tmp/漫画整理器.vbs`
- `.tmp/漫画导出器.vbs`

## 常见问题

<details>
<summary><strong>为什么双击 VBS 后没有黑色命令行窗口？</strong></summary>

这是正常设计。VBS 隐藏 PowerShell 控制台，只显示图形界面；关闭图形界面后后台进程随之退出。

</details>

<details>
<summary><strong>为什么漫画没有出现在工具列表中？</strong></summary>

确认漫画目录中至少有一张受支持格式的图片。图片既可以位于章节子文件夹，也可以直接位于漫画根目录。只有 JSON/HTML、没有图片的目录不会成为候选漫画。

</details>

<details>
<summary><strong>为什么分话 CBZ 导入 ReadEra 后变成很多本？</strong></summary>

ReadEra 会把每个 CBZ 当成独立文档。需要“一本书 + 可点击目录”时使用 EPUB；需要“一部漫画 + 多章节 + 无缝长条”时使用 Mihon 本地来源。

</details>

<details>
<summary><strong>整理器必须放在 new 文件夹吗？</strong></summary>

不必须。整理器只处理自己所在的文件夹，放在漫画根目录也能运行。单独建立 `new` 或“待整理”子文件夹只是为了降低误选和混淆的概率。

</details>

## 已知边界

- 完全没有数字规律的图片名只能自然排序，工具无法可靠证明是否缺页；
- 同一个文件夹混用多套命名规则时，建议先用整理器预览并确认；
- 超长路径可能受 Windows 或解压软件限制，建议不要嵌套得过深；
- HTML 阅读器适合本机离线阅读；跨设备同步进度、网络书库和多人共享不在项目范围内。
